## 12. Camera Cancel/Permission Behavior

**Status: B — Both collapse to `null`**

Both user cancellation and permission denial currently return `null` from `capturePhoto()`. The behavior is:

- Cancellation: caught via `message.includes('cancelled')` → returns `null` silently
- Permission denied: caught in general catch block → logs warning, returns `null`
- Camera unavailable: same general catch → returns `null`

**Impact:** Existing form data remains fully intact in all cases. No crash, no field clearing. This is a **small UX limitation** (user cannot distinguish "you cancelled" from "permission was denied") but is **not a correctness problem**. The `CameraPort` interface does not need to be redesigned for M9.1.

## 13. Android Camera Permission Audit

`android/app/src/main/AndroidManifest.xml` contains:

```xml
<uses-permission android:name="android.permission.CAMERA" />
```

**Finding:** The explicit `CAMERA` permission **is genuinely required**. The Capacitor Camera plugin with `CameraSource.Camera` invokes the device camera hardware directly. Without this declaration, Android will not grant the app access to the camera at runtime on API 23+. The `@capacitor/camera` plugin documentation confirms this requirement.

**No change needed.**

## 20. M9.1.1 — Cloudflare Pages CI Failure Resolution

### Root Cause Analysis

1. **Lockfile Out-of-Sync (`npm ci` failure)**:
   - In Cloudflare Pages CI runner (npm@10.9.2), `@apideck/better-ajv-errors` (transitive dependency of `vite-plugin-pwa` -> `workbox-build`) has peer dependency `ajv: ">=8"`.
   - In the previously committed `package-lock.json`, npm 10.8 had hoisted `ajv@6.15.0` (from `eslint`) to the top-level `node_modules/ajv`, and nested `ajv@8.20.0` under `workbox-build`.
   - When npm 10.9.2 on Cloudflare ran `npm ci`, its tree validator required that top-level `node_modules/ajv` satisfy the peer dependency of top-level `@apideck/better-ajv-errors` (`>=8`). It rejected `ajv@6.15.0` at the root as invalid and reported `Missing: ajv@6.15.0` (expected under `eslint`).
2. **Node Version Engine Warnings (`EBADENGINE`)**:
   - Cloudflare Pages default build image used `nodejs@22.16.0`.
   - `jsdom@30.0.1` and `undici@8.10.1` require Node `>=22.19.0` or Node 24 LTS.

### Fixes Applied

1. Added `"ajv": "^8.20.0"` to `devDependencies` in `package.json`.
   - This explicitly hoists `ajv@8.20.0` and `json-schema-traverse@1.0.0` to the root of `node_modules`, directly satisfying `@apideck/better-ajv-errors`.
   - `eslint` cleanly nests its required `ajv@6.15.0` under `node_modules/eslint/node_modules/ajv`.
   - Verified locally with `npx -p npm@10.9.2 npm ci`: passes with code 0 in 18 seconds.
2. Added `.node-version` and `.nvmrc` containing `24.20.0` at repository root.
   - Cloudflare Pages build runner automatically reads `.node-version` / `.nvmrc` and switches to Node 24 LTS, matching the local baseline and eliminating all `EBADENGINE` warnings.
